# When Foundation Models are One-Liners: Limitations and Future Directions for Time Series Anomaly Detection

This repository contains the official code, evaluation scripts, and pre-computed results for [our paper](https://openreview.net/forum?id=H27kvyG4qf) accepted at ICLR 2026.

Please follow the steps below to reproduce the results in the paper.

## Installation

To avoid dependency conflicts, we recommend creating separate virtual environments for different model families and for evaluating anomaly scores. We used Python 3.11 for all environments.

### [MOMENT](https://github.com/moment-timeseries-foundation-model/moment)
```bash
pip install momentfm
pip install pandas==2.2.3
```

### [TimesFM](https://github.com/google-research/timesfm)
```bash
pip install timesfm[torch]
```

### [Chronos](https://github.com/amazon-science/chronos-forecasting)
```bash
git clone https://github.com/autogluon/autogluon
cd autogluon && pip install -e timeseries/[TimeSeriesDataFrame,TimeSeriesPredictor]
```

### [Time-MoE](https://github.com/Time-MoE/Time-MoE)
Follow the installation instructions in the Time-MoE repository.

### [TSB-AD](https://github.com/thedatumorg/TSB-AD) (For evaluating anomaly scores)
```bash
pip install TSB-AD
```

## Data Preparation

### Datasets

Download and unzip [the TSB-AD-U dataset](https://github.com/thedatumorg/TSB-AD/tree/main/Datasets) and place the contents under `data/TSB-AD-U`.

### Our Results

Our experimental results are in `results/`. The intermediate results are large and can be downloaded from [here](https://rdr.kuleuven.be/dataset.xhtml?persistentId=doi:10.48804/MCVI4N) when needed.

## Evaluation (on the TSB-AD-U evaluation set)

**Note**: For comparison, all reproduction results will be in `reproductions/`, while our results are in `results/`. 

### Baselines

Evaluate the baselines by running `python scripts/evaluate_baselines.py <baseline_name> <win_size>`, e.g., `python scripts/evaluate_baselines.py var 64`, `python scripts/evaluate_baselines.py last 3`, or `python scripts/evaluate_baselines.py centered 5`. This should be done in the virtual environment created for evaluating anomaly scores, i.e., with TSB-AD installed.

Additionally, for comparison with TSPulse:

#### Ensemble

Run `python scripts/evaluate_baselines_ensemble.py <baseline_name_1> <win_size_1> <baseline_name_2> <win_size_2>`, e.g., `python scripts/evaluate_baselines_ensemble.py var 96 last 3`.

#### Triangulation

Run `python scripts/evaluate_baselines.py <baseline_name> <win_size> -t` to evaluate the baseline on the TSB-AD-U tuning set. Then, triangulation can be done based on performance on the tuning set.

### TSFMs

#### Ordinary Setting

1. Obtain anomaly scores by running `python scripts/run_tsfm_on_eva.py <script_name> <model_size> <window_size>`, e.g., `python scripts/run_tsfm_on_eva.py moment s 64`. This should be done in the virtual environment created for each TSFM family. The tables below show the mappings for `<script_name>` and `<model_size>`.

| script_name| Model Family | 
|------------|------------|
| moment_zs.py     | MOMENT          |
| chronos_zs.py     | Chronos-Bolt          |
| time-moe.py    | TimeMoE          |
| times_fm.py    | TimesFM          |

| Model Family | model_size: s | model_size: l           |
|------------|------------|-------------------------|
| MOMENT     | base          | large           |
| Chronos-Bolt    | small          | base    |
| TimeMoE    | base, 50M          | large, 200M     |
| TimesFM   | 1.0          | 2.0           |

2. Evaluate the anomaly scores from step 1 by running `python scripts/evaluate_anomaly_scores.py <folder_name>`, e.g., `python scripts/evaluate_anomaly_scores.py moment_base_64`, where `<folder_name>` is the name of the folder containing anomaly scores, generated by step 1. This should be done in the virtual environment created for evaluating anomaly scores, i.e., with TSB-AD installed.

#### Various Forecast Horizons

1. Obtain model forecasts by running `python scripts/run_tsfm_on_eva.py <script_name> <model_size> <window_size>`, where `<script_name>` can be `times_fm_long_horizon.py` or `chronos_long_horizon.py`. This should be done in the virtual environment created for each TSFM family.

2. Based on the model forecasts from step 1, calculate anomaly scores for various forecast horizons by running `python scripts/long_horizon_predictions_to_scores.py <model_name> <win_size>`. This should be done in the virtual environment created for evaluating anomaly scores, i.e., with TSB-AD installed.

3. Evaluate the anomaly scores from step 2 by running `python scripts/evaluate_anomaly_scores_horizons.py <folder_name> <horizon>`, where `<folder_name>` is the name of the folder containing anomaly scores, generated by step 2. This should be done in the virtual environment created for evaluating anomaly scores, i.e., with TSB-AD installed.

#### Normalization Ablations (as shown in Appendix I of the paper)

The steps are the same as in the Ordinary Setting. The table below shows the mappings for `<script_name>`.

| script_name| Model Family | Normalization Method |
|------------|------------|------------|
| moment_zs_global_z.py     | MOMENT        | Global Z |
| time-moe_global_z.py    | TimeMoE          | Global Z |
| times_fm_global_z.py    | TimesFM          | Global Z |
| moment_zs_minmax.py     | MOMENT          | Min-Max |
| time-moe_minmax.py    | TimeMoE          | Min-Max |
| times_fm_minmax.py    | TimesFM          | Min-Max |

Note that:

Z-normalization is an integral part of the pipelines of MOMENT and Chronos and cannot be disabled externally. 

In our ablation experiments, we manually modified the codebase of MOMENT to disable its Z-normalization and the corresponding de-normalization. For Chronos, we directly used [TSB-AD](https://github.com/thedatumorg/TSB-AD/tree/main)'s implementation for Chronos-t5 for comparison because the latter uses mean-scaling instead of z-normalization.
